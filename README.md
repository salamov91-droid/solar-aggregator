# Solar Aggregator

MVP-проект витрины решений по солнечной энергетике на вашем дизайне с подгрузкой каталога и цен с сайтов партнёров.

## Что умеет

- агрегировать решения с сайтов Volta Energy и e-solarpower;
- нормализовать позиции по типам: сетевые, гибридные, автономные;
- показывать вашу витрину и ваши CTA вместо партнёрского интерфейса;
- считать монтаж как 15% от стоимости оборудования;
- добавлять доставку и считать стоимость под ключ;
- обновлять каталог вручную через API или по cron;
- подбирать лучшее решение по параметрам объекта через встроенный калькулятор.

## Страницы

- `/` — главная страница с позиционированием, блоками преимуществ и подборщиком;
- `/catalog` — полный каталог решений;
- `/calculator` — отдельная страница калькулятора/подборщика.

## Логика калькулятора

Калькулятор принимает параметры объекта:

- тип объекта: коммерческий или частный дом;
- есть ли подключение к централизованной сети;
- главная задача: экономия, экономия + резерв, полная автономия;
- профиль потребления: небольшой, средний, высокий;
- частота отключений;
- предпочтительный партнёр;
- стоимость доставки.

На основе этих параметров:

1. определяется рекомендуемый тип решения;
2. каталог фильтруется до подходящих решений;
3. позиции ранжируются и показывается лучшее решение;
4. сразу считается цена под ключ.

## Архитектура

- `app/` — frontend и API routes на Next.js App Router;
- `app/components/` — UI-компоненты сайта, каталога и калькулятора;
- `lib/parsers/` — парсеры партнёрских сайтов;
- `lib/recommendation.ts` — логика рекомендаций и ранжирования;
- `lib/solutions.ts` — логика чтения кэша и обновления каталога;
- `public/solutions-cache.json` — локальный кэш решений после обновления;
- `app/api/refresh` — endpoint для ручного обновления прайса;
- `app/api/solutions` — endpoint для фронтенда и внешних интеграций.

## Быстрый старт

```bash
npm install
npm run dev
```

Открыть локально:

```bash
http://localhost:3000
```

## Обновление каталога

Вариант 1 — локально:

```bash
npm run refresh
```

Вариант 2 — через API:

```bash
curl -X POST http://localhost:3000/api/refresh \
  -H "Authorization: Bearer YOUR_SECRET"
```

## Переменные окружения

Создайте `.env.local`:

```bash
REFRESH_SECRET=change_me
```

## Что доработать следующим этапом

1. Перенести кэш в PostgreSQL или Supabase.
2. Добавить CRM-форму заявки и отправку лидов в Telegram/почту.
3. Сделать региональные тарифы доставки.
4. Улучшить парсеры под точную текущую HTML-разметку карточек партнёров.
5. Добавить брендирование, собственные страницы услуг и кейсов.
6. Сделать админку для ручной корректировки каталога.
7. Добавить детальные карточки решений и посадочные страницы под сегменты.

## Важное замечание

Парсинг по HTML зависит от структуры сайтов партнёров. Если они изменят верстку, селекторы в `lib/parsers/volta.ts` и `lib/parsers/eSolar.ts` нужно будет поправить.


## Запуск без терминала через Vercel

В проект добавлены файлы для деплоя через GitHub + Vercel без локального запуска:

- `.env.example`
- `vercel.json`
- `DEPLOY_VERCEL.md`

Для Vercel рекомендуется включить:

- `LIVE_CATALOG_MODE=true`
- `REFRESH_SECRET=your_secret`

В этом режиме каталог подтягивается напрямую с сайтов партнёров при запросе к API. Если парсинг временно не сработал, сайт покажет встроенные fallback-данные.
